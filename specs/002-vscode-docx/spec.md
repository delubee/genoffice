# Feature Specification: 同一 VS Code 插件中的 DOCX 编辑与原生 AI 交互

**Feature Branch**: `feature/vscode-docx`

**Created**: 2026-10-24

**Status**: Ready for planning

**Input**: 在现有 GenOffice 插件中增加 DOCX，保留插件 ID 和 XLSX 功能。不同格式使用独立编辑器并按需加载。Word 风格默认、可切换跟随 VS Code；支持手工和 AI 编辑，继续使用 VS Code 原生聊天、技能及工作区 Python。首版完成正文、标题、常用格式、列表、基本表格及可靠保存闭环。

## User Scenarios & Testing _(mandatory)_

### User Story 1 - 一个插件打开与编辑两类文档 (Priority: P1)

用户升级已有插件后，通过 Open With 打开 DOCX，在 Word 风格的文档页面编辑；同时打开的 XLSX 保持已有编辑方式。

**Why this priority**: 不增加安装和维护成本，先交付实际可用的 Word 编辑闭环。

**Independent Test**: 同一窗口打开一个 DOCX 和一个 XLSX，分别修改、保存、关闭并重开，检查两者内容互不影响。

**Acceptance Scenarios**:

1. **Given** 已安装现有插件，**When** 升级后打开 DOCX，**Then** 无需第二个插件即可显示可编辑的正文与基本表格，原 XLSX 打开方式和设置保留。
2. **Given** 包含段落、标题、列表、字体格式和基本表格的文档，**When** 用户输入、删除、换行及修改这些格式，**Then** 修改可保存，并在重开后保持文字、结构及支持的格式。
3. **Given** 同时打开两个 DOCX 与一个 XLSX，**When** 用户交替操作，**Then** 各文档维护独立的内容、选区、撤销历史和保存状态。

### User Story 2 - 原生聊天读取并修改当前未保存内容 (Priority: P1)

用户在 VS Code 原生聊天中绑定明确的 Word 文档和选区，读取未保存内容，要求润色、替换、插入段落或调整基本格式；手工修改和 AI 修改进入同一历史。

**Why this priority**: 延续现有原生聊天、技能与编程工作流，避免第二套聊天界面。

**Independent Test**: 手工输入未保存句子，原生工具读到该句并原子替换选定段落；一次撤销恢复 AI 修改前的状态，再撤销恢复手工修改前的状态。

**Acceptance Scenarios**:

1. **Given** DOCX 有未保存的手工编辑，**When** 已绑定文档的聊天工具读取，**Then** 返回当前内容和当前版本，不用磁盘旧内容代替。
2. **Given** AI 已读内容后用户又修改文档，**When** AI 提交旧版本修改，**Then** 拒绝提交并要求重读，文档不发生部分修改。
3. **Given** 用户打开多个文档，**When** 工具未指定绑定目标，**Then** 返回可选文档，不根据焦点猜测要写的文件。
4. **Given** 一批 AI 操作中有一个无效目标或不支持操作，**When** 提交，**Then** 整批拒绝；相同事务重试不重复插入内容。

### User Story 3 - 编程辅助与可靠保存恢复 (Priority: P2)

用户通过原生技能和工作区程序分析或生成选区内容，经显式预览和版本校验回写；保存、撤销、备份和恢复与编辑器保持一致。

**Why this priority**: 满足已明确的编程工作流，并防止覆盖正在编辑的原文件或丢失未保存修改。

**Independent Test**: 导出包含未保存修改的段落，程序生成结构化替换结果，预览后一次提交；保存、撤销、重做及重新打开核对结果。

**Acceptance Scenarios**:

1. **Given** 用户选择了段落，**When** 导出给工作区 Python，**Then** 获取当前版本的结构化内容，程序不直接覆盖打开的 DOCX。
2. **Given** 已生成结果后原文档发生变化，**When** 尝试回写，**Then** 拒绝旧结果，保留用户的新修改。
3. **Given** 原文件被外部程序修改，**When** 用户保存，**Then** 提示冲突，保留未保存修改，并支持另存为或重新加载。
4. **Given** 编辑器关闭或故障后恢复备份，**When** 重开恢复文档，**Then** 恢复未保存状态；旧聊天绑定不能继续写入新会话。

### User Story 4 - 保留原文档与可预期的外观 (Priority: P2)

用户希望只改正文时保留已有图片、页眉页脚、其他未修改内容，并能切换界面风格而不改变文档本身。

**Why this priority**: 可读写不等同于可可靠使用；首版需明确保真边界。

**Independent Test**: 打开含图片、页眉页脚及高级内容的样例，仅修改一个普通段落，保存后核对未涉及的内容；切换外观后核对保存结果。

**Acceptance Scenarios**:

1. **Given** 文档包含暂不可编辑的高级内容，**When** 显示并修改无关普通段落，**Then** 高级内容保留；无法安全修改的位置明确呈现只读，不悄悄删除内容。
2. **Given** 默认 Word 风格的文档，**When** 切换跟随 VS Code，**Then** 当前内容、选区、未保存状态和历史保留；文档字体色、底纹和保存内容不被主题改写。
3. **Given** 用户只打开 XLSX，**When** 插件激活该文档，**Then** 不初始化 Word 编辑器；反向亦成立，文档类型之间不会加载彼此的编辑实例。

### Edge Cases

- 空白文档、中文与组合输入、长段落、多段选择、表格单元格内输入及粘贴。
- 加密、损坏、受保护、超出首版容量的文件；明确拒绝或只读，不创建会覆盖原文件的空白替代品。
- 图片、复杂表格、修订、批注、目录、浮动对象和内容控件；只读保护与未修改内容保留。
- 编辑过程中提交 AI、输入法组合未结束时读取、视图关闭后仍有工具请求。
- 同一文件的路径别名、Windows junction/虚拟盘、外部修改和另存为目标已存在。
- 程序交换文件越界、格式无效、结果过期、重复提交和取消。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: MUST 保留现有插件 ID、XLSX 自定义编辑器标识、工具名称及设置兼容性；一次安装同时支持 DOCX/XLSX。
- **FR-002**: MUST 按文件类型启用独立编辑器；只打开一种类型时不创建另一类型的编辑实例。
- **FR-003**: MUST 通过 Open With 打开本机或扩展宿主可访问的 `.docx`，显示受支持的可编辑内容及未支持内容的明确边界。
- **FR-004**: MUST 支持正文输入、删除、段落拆分/合并、标题、常用字体/字号/加粗/斜体/下划线/文字颜色、段落对齐和基本列表。
- **FR-005**: MUST 支持基本矩形表格的单元格文字编辑及行列增删；复杂合并或嵌套结构不支持时明确保护。
- **FR-006**: MUST 默认显示 Word 风格界面，提供跟随 VS Code 的选择；外观切换不得重置文档状态或改写文档数据。
- **FR-007**: MUST 将手工、AI、程序回写的编辑汇入每文档统一、版本化的历史，支持 VS Code 原生保存、另存为、撤销重做及脏状态。
- **FR-008**: MUST 读取当前未保存内容，并提供稳定的文档/段落目标、选区及版本；输入组合未结束时明确等待或拒绝读取，不返回旧内容冒充当前内容。
- **FR-009**: MUST 仅通过原生聊天工具与技能接入 AI；不内置第二套聊天、模型配置、凭据或程序执行器。
- **FR-010**: MUST 提供有界的段落读取、替换、插入、删除和支持的格式修改；多操作提交原子化，检查目标版本，支持事务重试查询并防止重复应用。
- **FR-011**: MUST 明确绑定文档，关闭/重载/恢复后的会话使用新身份；不根据窗口焦点隐式选择写入目标。
- **FR-012**: MUST 支持导出当前结构化内容并对程序结果进行路径、格式、大小、目标及版本校验，预览后经同一编辑历史回写。
- **FR-013**: MUST 防止直接用程序修改磁盘原文件替代插件回写；工作区程序继续使用原生终端与其既有授权流程。
- **FR-014**: MUST 保留未修改的原文档内容、关系及资源，尤其图片、页眉页脚和不支持的对象；无法可靠保留的修改明确拒绝。
- **FR-015**: MUST 检测文件保护及不可编辑内容，手工和 AI 遵守相同约束，不将高级内容静默转换为普通文本。
- **FR-016**: MUST 检测外部修改与保存目标冲突，保存失败保留编辑状态和可恢复结果；不自动覆盖外部新版本。
- **FR-017**: MUST 支持未保存内容备份与恢复，保存成功不破坏后续撤销重做的内容一致性。
- **FR-018**: MUST 为损坏、加密和容量超限文件提供可理解的错误，不修改原文件；不承诺首版解密、完整 Word 排版或高级对象编辑。
- **FR-019**: MUST 对原文件内容、程序结果和工具读取内容按文档数据处理，不执行其中的指令或外部程序。
- **FR-020**: MUST 在同一发布包中验证 DOCX 与 XLSX 共存、按需加载、独立状态及现有 Windows 虚拟盘路径兼容性。

### Key Entities

- **Word 文档会话**: 文档身份、原始内容、当前内容、版本、选区、脏状态及保护状态。
- **段落/内容块目标**: 可稳定识别的正文或表格结构位置；不以编辑后漂移的临时序号作为无版本写入凭据。
- **编辑事务**: 明确来源、预期版本、唯一事务身份、原子操作集合和提交结果。
- **历史与备份**: 可序列化的内容版本，用于撤销、重做及恢复。
- **程序交换计划**: 导出时的文档/版本/目标、结构化结果、预览及受控回写状态。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 单次安装的验收样例中，DOCX 与 XLSX 均完成打开、编辑、保存、关闭重开；两类文档无状态串扰，已有 XLSX 核心回归全部通过。
- **SC-002**: 正文、标题、列表、常用字体格式及基本表格的约定样例，保存重开后支持的内容和结构核对通过率为 100%。
- **SC-003**: 连续交替执行至少 20 次手工/工具编辑并跨越一次保存后，撤销重做结果与预期版本逐步一致；过期和重复请求不会造成部分或重复修改。
- **SC-004**: 图片、页眉页脚及高级内容保留样例中，无关正文编辑不会导致未涉及内容或资源丢失；受保护修改与超限操作全部在提交前拒绝。
- **SC-005**: 在约定测试主机上，1 MiB 以内、200 个正文段落和 10 张基本表格的样例，冷打开到可编辑不超过 10 秒；100 字以内的普通编辑在 1 秒内完成可见反馈。
- **SC-006**: 外观切换、外部文件冲突、编辑器关闭和备份恢复的验收样例，均保留或明确恢复未保存修改，不出现无提示的数据丢失。
- **SC-007**: 至少一份程序交换样例使用当前未保存内容，能够预览并回写结果；过期结果、越界路径及无效格式全部拒绝。
- **SC-008**: Windows 的真实编辑器与安装包验证覆盖 DOCX/XLSX 共存和保存重开，未执行的真实模型或其他平台验证明确标识。

## Assumptions

- 本功能在一个现有插件中交付；不新建第二个插件，也不更换已安装插件的身份。
- 首版以已有 DOCX 的常用正文编辑闭环为范围；图片初期展示/保留，图片位置调整、页眉页脚编辑、修订批注、目录刷新等高级功能另行推进。
- Word 风格指页面和常用功能区体验，不承诺与 Microsoft Word 字体度量或分页逐像素相同；正式验收分别核对内容保真与展示边界。
- 受保护和复杂内容以可解释的只读/拒绝方式处理，保留原始内容；不以覆盖格式的方式简化保存。
- 原生聊天的模型与技能发现沿用用户的 VS Code 环境；测试工具调用不等同于真实模型成功使用技能，分别记录证据。
