/speckit-specify 为 GenOffice 新增 VS Code 文档编辑扩展，使用户在 VS Code 编辑区打开、查看并手工编辑 Office 文档，同时通过 VS Code 原生聊天中的 Agent 使用技能、编写和执行 Python 等程序来分析数据、修改文档。沿用用户现有的聊天、模型选择、账户、终端和编程环境，插件不重新构建聊天或模型服务。

用户已确认：
1. 使用 VS Code 原生聊天及其技能、编程和终端能力。
2. 支持手工编辑和 AI 编辑，两者处理同一个当前文档；界面实时反映成功应用的修改。
3. Python 可参与复杂计算，插件提供当前数据与计算结果之间的交换能力。
4. 本轮只生成提示词、需求规格及质量检查，不编写实现代码，不自动进入规划或实现。

范围默认值（必须标记为待评审假设，不得冒充用户已确认）：首版以桌面 VS Code 中 .xlsx 完整闭环为范围，Word、PPT、PDF、Markdown、HTML 的专用适配后续分别规划。浏览器版、多人协同、其他 AI 客户端和其他计算语言的专门集成不作为首版验收条件。远程工作区、操作系统覆盖和最低版本在后续规划明确验证边界。

需求应覆盖：
- 从文件树打开工作簿，查看多工作表、值、公式及常用格式，手工编辑、保存和另存为原生 .xlsx。
- 原生聊天中的 AI 获取明确文档、工作表、数据范围、选区和版本，按需读取当前内容，包括尚未保存的手工修改；修改值、公式、格式，创建汇总工作表和图表。
- 聊天获取焦点或用户切换标签页时，已经绑定的任务不静默换目标；同名文件、无选区、目标歧义、关闭重开及结构性变更都有明确行为。
- 提供原生聊天可使用的文档技能：简单修改直接操作文档，复杂分析通过工作区 Python；保留用户查看脚本、输入快照和结果的能力。
- 大范围数据可通过文件供程序处理，结果从文件写入指定区域或新工作表，无需全部记录经过模型上下文。保留数字、百分比、日期、布尔、空值及文本编号语义，区分公式和计算结果。
- 程序输入基于当前未保存状态。结果回写前校验来源、目标、版本、数据和容量，不以直接覆盖已打开磁盘文件绕过文档状态；过期结果、外部修改及文档关闭时保留用户已有编辑并明确报告。
- 手工与 AI 共用保存、未保存标记、撤销/重做、关闭提示及恢复行为；AI 一批修改形成一个可撤销步骤，无法保证撤销的操作在执行前报告。
- 校验修改批次；失败批次不得留下静默部分写入，多批任务准确报告成功、失败和取消部分。

按项目有效模板生成优先级用户故事、独立验证方法、Given/When/Then 场景、边界条件、可测试功能需求、关键实体、量化成功标准、依赖及范围假设。成功标准描述用户可观察结果，区分目标和已测结果。不要指定 Webview、API、通信协议、框架或目录结构等实现方案。仅当确无合理默认值时提出最多三个关键澄清问题。另生成需求质量检查清单。
