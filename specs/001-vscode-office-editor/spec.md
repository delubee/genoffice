# Feature Specification: VS Code 原生聊天驱动的 Office 文档编辑

**Feature Branch**: `main`（本次未配置分支创建钩子，规格目录独立于分支）

**Created**: 2026-10-21

**Status**: Draft — 需求质量检查通过，待评审范围假设

**Input**: User description: 将 GenOffice 文档编辑能力集成到 VS Code；支持手工与 AI 编辑；聊天、技能和 Python 等编程能力使用 VS Code 原生功能。完整调用输入见 [specify-prompt.md](specify-prompt.md)。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在 VS Code 内打开并手工编辑工作簿 (Priority: P1)

作为文档使用者，我希望在 VS Code 编辑区查看并修改 Excel 工作簿，在处理代码和数据时使用同一工作环境。

**Why this priority**: 独立可用的文档编辑能力是 AI 编辑的基础，不应依赖模型或 Python。

**Independent Test**: 关闭 AI，打开包含两个工作表、常用格式和基础公式的工作簿，手工修改、保存并重新打开，核对内容和结果。

**Acceptance Scenarios**:

1. **Given** 工作区存在有效 .xlsx，**When** 用户选择使用扩展打开，**Then** 工作表、值、公式和受支持格式在 VS Code 编辑区可见，与源文件一致。
2. **Given** 工作簿已打开，**When** 用户切换工作表、修改值、基础公式或常用格式，**Then** 修改可见，文档标记为未保存，受支持公式更新计算结果。
3. **Given** 存在未保存修改，**When** 保存或另存为后重新打开，**Then** 目标 .xlsx 保留修改；另存为不改动原件，覆盖既有目标需用户明确选择。
4. **Given** AI 未配置或网络不可用，**When** 用户手工编辑和保存，**Then** 受支持的文档功能仍可用，不要求额外的文档 AI 账户。
5. **Given** 工作簿有受保护区域或不可编辑对象，**When** 用户尝试修改，**Then** 尊重其约束并说明拒绝原因，不破坏现有数据。

---

### User Story 2 - 使用原生聊天读取并修改当前文档 (Priority: P1)

作为原生聊天使用者，我希望 AI 理解当前文档和选区，直接修改可视编辑器中的文档，并准确说明完成情况。

**Why this priority**: 这是用户明确要求的原生聊天与 AI 编辑闭环，无需程序分析就能独立展示价值。

**Independent Test**: 从原生聊天完成一次区域问答和一次公式、格式、工作表及图表修改，检查当前数据、任务目标和实际执行结果。

**Acceptance Scenarios**:

1. **Given** 单元格有未保存的手工修改，**When** AI 读取相关区域，**Then** 获取当前编辑值，而非仅磁盘旧值。
2. **Given** 任务开始时绑定工作簿 A 的选区，**When** 焦点进入聊天或用户切换到 B，**Then** 已绑定任务仍针对 A 和原选区；无选区或目标有歧义时先明确目标，不猜测。
3. **Given** AI 已读取相关区域且版本未改变，**When** 请求设置值、公式、格式、新增汇总工作表或图表，**Then** 成功修改在当前编辑器可见，反馈与实际结果一致。
4. **Given** 用户只要求解释或统计，**When** AI 完成回答，**Then** 文档不被修改，不遗留用于回答的临时单元格。
5. **Given** 打开了路径不同的同名工作簿，**When** 请求修改明确目标，**Then** 只修改指定文件，无法确定目标时要求选择。
6. **Given** 修改超出实际支持范围或容量，或结果已经成功提交，**When** 请求执行或重试，**Then** 分别明确拒绝、指导分批或报告已应用，不静默截断或重复新增内容。

---

### User Story 3 - 使用 Python 分析并回写当前数据 (Priority: P1)

作为数据分析用户，我希望 AI 在工作区编写和运行 Python，以当前文档数据完成清洗或分析，再将结果写入可继续编辑的工作簿。

**Why this priority**: 使用原生编程环境是用户的明确动机，应独立验证程序与当前文档的连接。

**Independent Test**: 对已有正确答案的销售数据进行未保存手工修改，通过原生聊天执行程序汇总，比较结果、源数据和回写位置。

**Acceptance Scenarios**:

1. **Given** 销售数据包含未保存修改，**When** 请求“用 Python 按地区汇总销售额，新增汇总表和图表”，**Then** 输入包含该修改，汇总正确，并显示在同一文档的新工作表中。
2. **Given** 分析区域有 100,000 个单元格，**When** 通过程序分析，**Then** 可以通过文件传递完整数据和结果，无需全部记录在聊天中逐条出现。
3. **Given** 输入包含数字、百分比、日期、布尔、空值及以零开头的文本编号，**When** 导出和回写，**Then** 保留声明的数据语义，区分公式、计算结果及显示格式，不误转换文本编号。
4. **Given** 程序产生结果文件，**When** 请求回写明确区域，**Then** 校验来源、目标、版本、完整性、内容与容量后应用；无关原数据不改写，结果可手工编辑与撤销。
5. **Given** Python、依赖缺失，脚本失败或执行被取消，**When** 分析无法完成，**Then** 明确指出未完成步骤，不导入不完整输出，不损害已有手工修改。
6. **Given** 程序已经运行，**When** 用户核查过程，**Then** 可从原生聊天或工作区查看实际脚本、输入快照标识和结果位置。

---

### User Story 4 - 避免过期任务覆盖新修改 (Priority: P1)

作为同时手工编辑与使用 AI 的用户，我希望回写基于明确的数据版本，避免旧结果覆盖新的内容。

**Why this priority**: 混合编辑的可信性取决于一致性，可用受控并发修改独立检验。

**Independent Test**: 在读取和回写之间分别进行手工修改、行插入、外部文件覆盖和关闭重开，检查拒绝、重新读取及数据保留行为。

**Acceptance Scenarios**:

1. **Given** 任务读取版本 A，**When** 文档变为版本 B 后请求应用旧结果，**Then** 拒绝回写并要求重新读取，B 的内容不变。
2. **Given** 任务读取了单元格坐标，**When** 行列或工作表结构发生变化，**Then** 原位置依据失效，后续修改须获得新版本与位置。
3. **Given** 文档有未保存修改，**When** 其他程序改变磁盘文件，**Then** 报告冲突，保留双方内容，提供重新加载或另存为入口，不静默覆盖。
4. **Given** 结果绑定某次打开的文档，**When** 文档关闭或重新打开后旧任务继续，**Then** 旧任务不能修改新会话。
5. **Given** 一批操作包含非法操作或执行中失败，**When** 返回失败，**Then** 文档恢复到该批次执行前状态，不留下部分写入。

---

### User Story 5 - 统一保存、撤销、重做和恢复 (Priority: P1)

作为编辑者，我希望控制任何来源的文档修改，并在保存失败、取消或异常退出后保留可恢复的工作。

**Why this priority**: 用户必须能够撤销错误，可用确定的编辑序列独立验证。

**Independent Test**: 按“手工—AI—手工”修改，逐步撤销与重做；保存后继续撤销并再次保存；另测关闭、异常恢复和失败保存。

**Acceptance Scenarios**:

1. **Given** 手工修改与一批成功 AI 修改，**When** 依次撤销和重做，**Then** 按发生顺序恢复对应状态，一次撤销可还原整批 AI 修改。
2. **Given** 文档已保存且未关闭，**When** 撤销此前修改，**Then** 恢复先前内容并重新标记未保存；保存不会自行清空可用撤销历史。
3. **Given** 修改超出可撤销容量，**When** 无法保证整批撤销，**Then** 在修改前拒绝并建议缩小批次，不在应用后才告知无法撤销。
4. **Given** 存在未保存修改，**When** 用户关闭，**Then** 可选择保存、放弃或取消关闭；取消保留文档及修改。
5. **Given** 最近一次恢复副本已确认写入，**When** 异常结束后重新打开，**Then** 提供恢复入口并标明副本时间，不自动覆盖原文件。
6. **Given** 任务分多批执行，**When** 用户取消或后续批次失败，**Then** 已完成批次保留且可撤销，当前失败批次无残留，反馈区分已完成和未完成部分。
7. **Given** 磁盘满、目标只读或用户取消另存为，**When** 保存无法完成，**Then** 不宣称成功，未保存内容及撤销能力保留。

---

### User Story 6 - 通过技能指导原生 Agent 完成文档任务 (Priority: P2)

作为原生聊天使用者，我希望启用文档技能后，AI 按任务选择正确的读取、编辑或程序分析流程，减少重复说明。

**Why this priority**: 技能提高任务复用性；先独立验证文档工具，再验证技能指导效果。

**Independent Test**: 启用文档技能，在原生聊天分别执行简单编辑、只读问答、程序分析和错误恢复，核查当前文档处理流程与结果。

**Acceptance Scenarios**:

1. **Given** 文档技能和所需工具可用，**When** 请求简单编辑或复杂分析，**Then** AI 先明确当前目标和数据，再分别直接编辑或使用程序快照计算并校验回写，用户无需复制整份文档到聊天。
2. **Given** 用户设置了原生 Agent 权限和执行确认规则，**When** 文档技能使用工具或运行程序，**Then** 遵守同样的规则，不另行绕过。
3. **Given** 原生聊天或所需工具未启用，**When** 用户尝试 AI 编辑，**Then** 获得明确启用说明，手工编辑仍可用。
4. **Given** 用户修改了已安装的文档技能，**When** 再次安装或更新，**Then** 能核查或确认替换，不静默覆盖用户内容。

### Edge Cases

- 损坏、加密或不支持的文件不得被显示成可保存的空工作簿，从而覆盖原件。
- 不支持编辑的原有特性必须保留；无法保证保留时阻止有损保存，明确说明原因。
- 超出读取、修改、计算或保存容量时，应说明真实边界；可分批任务提示分批，不以地址空间夸大容量。
- 无选区、多目标歧义、同名文件、选区变化和目标关闭时不能猜测；已绑定任务不因焦点变化换目标。
- 隐藏工作表、合并单元格、受保护区域及透视表输出的写入约束对手工与 AI 一致适用。
- 空区域、公式错误、尚未算完的结果、空输出与合法零值必须区分；空结果不默认为清空目标。
- 缺失、损坏、来源不符、内容被改变或版本过期的结果不得导入。
- 重复提交不得静默重复应用同一修改或新增同名工作表。
- 取消、保存、关闭及界面暂时不可见时，读取应返回有效当前状态或明确不可用，不能退回磁盘旧版本。
- 保存失败保留当前编辑；异常恢复以最近一次已确认写入的副本为边界，不承诺尚未形成副本的修改可恢复。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在桌面 VS Code 编辑区打开并编辑有效 .xlsx 的工作表、值、基础公式及常用格式。（US1）
- **FR-002**: 系统 MUST 支持保存、另存为、重开和未保存标记；保存失败或取消不丢失当前内容。（US1、US5）
- **FR-003**: 系统 MUST 在 AI、网络或 Python 不可用时保持受支持的离线手工编辑。（US1、US3、US6）
- **FR-004**: AI 交互 MUST 使用现有原生聊天、模型配置和执行环境，无须额外文档聊天、模型账户或密钥。（US2、US6）
- **FR-005**: 系统 MUST 为获准的 Agent 提供文档身份、工作表列表、当前工作表、数据范围、选区、未保存状态与版本依据。（US2、US4）
- **FR-006**: AI 读取 MUST 包含未保存修改，按需返回区域值、公式、格式及相关现有特性；不可读取时明确报错。（US2）
- **FR-007**: 系统 MUST 将已开始任务绑定明确文档与必要选区；焦点或标签页切换不静默换目标，歧义先明确。（US2、US4）
- **FR-008**: 系统 MUST 支持 AI 修改值、公式、常用格式并创建工作表和图表，成功应用的修改在当前编辑器可见。（US2）
- **FR-009**: 查询任务 MUST 不改变文档；修改反馈 MUST 依据实际执行结果说明目标及摘要。（US2）
- **FR-010**: 系统 MUST 提供适用原生聊天的文档技能及启用方式，覆盖读取、编辑、程序分析、检查和错误恢复；更新不静默覆盖用户修改。（US6）
- **FR-011**: 系统 MUST 将当前数据快照导出到获准的工作区位置供程序处理，并提供来源、区域、版本与数据语义，无需逐条复制到聊天。（US3）
- **FR-012**: 系统 MUST 支持 AI 使用工作区 Python 处理快照，提供可查看的脚本与结果位置，遵守原生执行权限及确认规则。（US3、US6）
- **FR-013**: 系统 MUST 将结果文件回写明确区域或新工作表，结果可手工编辑；不改动无关原数据。（US3）
- **FR-014**: 系统 MUST 在导入前校验来源、完整性、目标、版本、大小及内容，拒绝缺失、被改变或不完整结果。（US3、US4）
- **FR-015**: 数据交换 MUST 区分原始值、显示含义、公式及结果，保留数字、百分比、日期、布尔、空值与文本标识的声明语义。（US3）
- **FR-016**: AI 和程序回写 MUST 经过当前文档受控编辑，不能直接覆盖已打开文件来绕过未保存状态、版本及撤销记录。（US3、US4）
- **FR-017**: 系统 MUST 拒绝过期版本回写并要求重新读取；结构变化使原位置依据失效。（US4）
- **FR-018**: 磁盘文件与编辑状态冲突时，系统 MUST 保留双方并提供明确处理入口，不静默覆盖。（US4）
- **FR-019**: 文档关闭或重开时 MUST 使旧任务的写入资格失效，即使新旧路径相同。（US4）
- **FR-020**: 系统 MUST 校验修改批次，失败批次不留部分变化；多批任务分别报告成功、失败和取消部分。（US4、US5）
- **FR-021**: 每个成功 AI 修改批次 MUST 作为可撤销步骤，与手工修改按发生顺序支持撤销和重做；无法保证撤销时执行前拒绝并指导缩小批次。（US5）
- **FR-022**: 同次打开期间，保存 MUST 保留可用撤销/重做历史，撤销已保存修改重新标记未保存。（US5）
- **FR-023**: 系统 MUST 提供关闭时保存、放弃、取消及异常后恢复最近已确认副本的能力，标明副本时间。（US5）
- **FR-024**: 系统 MUST 区分程序失败、缺少依赖、取消与成功，不导入不完整输出；取消保留已完成可撤销批次。（US3、US5）
- **FR-025**: 手工和 AI 编辑 MUST 共同遵守文档保护及可编辑范围约束，不支持操作明确说明原因。（US1、US2、US4）
- **FR-026**: 系统 MUST 保留未修改内容及可保留原特性，无法保证保留时不得静默生成有损保存结果。（US1、US3）
- **FR-027**: 系统 MUST 明确读取、修改、计算与保存边界，可分批任务支持分批，超限保留文档并说明原因。（US2、US3、US5）
- **FR-028**: 系统 MUST 提供原生 Agent 所需文档操作的发现及错误反馈；重复提交不产生未报告的重复效果。（US2、US6）

### Key Entities *(include if feature involves data)*

- **打开的文档**: 文件身份、来源位置、当前内容、工作表、版本及未保存状态；区分同名文件及同路径的不同打开会话。
- **任务上下文**: 文档、选区、读取版本及执行进度；焦点变化不改变绑定目标。
- **数据快照**: 当前编辑状态的分析输入，包含来源、区域、版本、类型及公式语义。
- **计算结果**: 程序输出、来源快照、输出语义和目标建议，须校验后成为文档修改。
- **修改批次**: 共同目标、前置版本及执行状态的一组操作；成功批次可撤销，失败批次无残留。
- **历史与恢复副本**: 撤销/重做记录和最近已确认写入的恢复内容，区别于用户明确保存的原件。
- **文档技能**: 供原生聊天使用的任务指导与资料，描述读取、分析、修改及检查，具有可识别版本。

## Success Criteria *(mandatory)*

### Measurable Outcomes

以下均为待实现的验收目标，不代表当前版本已达到。后续规划须固定并公开参考设备、数据样本及计时方法，将本地处理与模型等待、外部程序运行分开计时。

- **SC-001**: 对包含 10,000 行、10 列、两个工作表及常用格式的参考工作簿，20 次打开至少 19 次在 10 秒内进入首屏可编辑状态；不计首次依赖准备。（US1）
- **SC-002**: 全部预设手工编辑、保存、另存为和重开用例保持预期值、公式及受支持格式，受检查的未修改内容无非预期变化。（US1）
- **SC-003**: 全部预设混合编辑用例中，AI 使用任务读取时的未保存内容；切换焦点、同名文件、关闭重开及过期回写用例中错误目标写入为零。（US2、US4）
- **SC-004**: 固定 100,000 单元格销售数据完成“未保存修改—程序汇总—新工作表与图表—保存重开”；地区汇总全部符合预先计算的正确答案，原始数据无无关改写，完整记录无需逐条出现于聊天。（US3）
- **SC-005**: 对已校验、最多 1,000 个普通单元格的修改批次，20 次至少 19 次在 2 秒内显示完整修改；不计模型生成、公式计算及外部程序时间。（US2）
- **SC-006**: 全部预设批次失败、程序失败、输出损坏及取消用例中，不完整当前批次的残留写入为零，多批任务报告与实际一致。（US3、US4、US5）
- **SC-007**: 固定“手工—AI—手工”序列在保存前后的撤销/重做均恢复预期状态，关闭取消及恢复用例无非预期覆盖。（US5）
- **SC-008**: 启用技能及必要原生工具后，简单编辑、只读问答、程序分析三类预设任务均可在原生聊天完成，无须额外聊天界面或模型凭据。（US2、US3、US6）

## Assumptions

- **用户已确认**: 使用 VS Code 原生聊天、技能及 Python 等编程能力，同时支持手工与 AI 编辑。本轮只产出提示词、规格与质量检查。
